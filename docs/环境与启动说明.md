# 环境与启动说明（IIP 设备检修诊断）

> 版本：V1.0　　适用：本地开发与演示环境（Windows + WSL2）

---

## 0. ⚠ 启动顺序（必须遵守）

**第 1 步永远是在 WSL2 Ubuntu 中启动 bge 向量模型服务**，否则 A2 知识检索的稠密向量无法生成，诊断链路会在检索节点失败。

```
① WSL2 Ubuntu：启动 bge-large-zh-v1.5 模型服务（SGLang，端口 30000）
        ↓ 验证：Windows 侧能访问 http://localhost:30000/v1/models
② Windows：准备数据（重跑传感器数据生成脚本）
        ↓
③ Windows：启动 FastAPI 服务（uvicorn）
        ↓
④ 浏览器/接口发起诊断请求
```

---

## 1. WSL2：启动向量模型服务（第 1 步）

在 WSL2 Ubuntu 中启动 SGLang 的 OpenAI 兼容服务（**按你已部署好的启动脚本为准**，下面是通用形式）：

```bash
# WSL2 Ubuntu 内执行
python -m sglang.launch_server \
    --model-path /home/yumo_unix2204/models/hub/models--BAAI--bge-large-zh-v1.5/snapshots/79e7739b6ab944e86d6171e44d24c997fc1e0116 \
    --port 30000 \
    --is-embedding \
    --host 0.0.0.0
```

服务启动后，在 **Windows 侧**验证（WSL2 的 localhost 会自动转发）：

```powershell
Invoke-WebRequest http://localhost:30000/v1/models -UseBasicParsing | Select-Object -ExpandProperty Content
# 期望返回包含 models--BAAI--bge-large-zh-v1.5/snapshots/... 的 JSON
```

模型参数：**bge-large-zh-v1.5，1024 维**，与 `.env` 的 `DIMENSION=1024` 一致。
注意：bge-v1.5 系列**不需要 query instruction**，query 与 passage 同样编码（加指令反而略掉点）。

## 2. Windows：Python 环境

| 项 | 值 |
| --- | --- |
| 解释器 | `D:\Anaconda\python.exe`（**Python 3.12.4**，Anaconda base） |
| 为什么不用系统自带的 3.14 | torch / langgraph / chromadb 等生态对 3.14 支持不完整，3.12 是当前最稳的版本 |
| 项目根 | 仓库根目录（所有命令在此执行，并设置 `PYTHONPATH=.`） |

安装依赖（**需要写 Anaconda 目录，若被文件沙箱拦截需提权或手动执行**）：

```powershell
& 'D:\Anaconda\python.exe' -m pip install openai fastapi "uvicorn[standard]" pydantic-settings ^
    python-docx pymysql jieba langgraph chromadb -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> 说明：`pip` 需要写入 `D:\Anaconda`（工作区之外）。若在受限沙箱/权限不足的环境下执行失败，请**在普通终端里手动执行**上述命令。
> 已实测安装成功的关键包：openai 3.16 / fastapi / uvicorn / pydantic-settings / python-docx / pymysql / jieba / langgraph 1.2.11 / chromadb 1.5.9。

## 2.5 Windows：构建知识库索引（首次或文档变更后）

```powershell
$env:PYTHONPATH='.'
& 'D:\Anaconda\python.exe' scripts\build_index.py
```

产物：`data/index/`（BM25 索引 + 向量库 + `index_meta.json`）。616 个知识块，约 6 秒完成。

**向量库后端**：默认 `VECTOR_STORE=memory`（numpy 内存库）。原计划的 ChromaDB 在本机不可用
（1.5.9 原生崩溃、0.4.24 需 MSVC Build Tools 编译），已提供接口一致的等价实现；
若后续装好编译环境，设 `VECTOR_STORE=chroma` 即可切回，无需改代码。

## 3. Windows：准备传感器数据（第 2 步）

数据基准时间 `data_now` = **真实系统时间**，因此**每次启动/演示前都要重跑**，让数据末端跟到当前时刻：

```powershell
$a = (Get-Date).AddHours(-72).ToString('yyyy-MM-ddTHH:mm:ss')
& 'D:\Anaconda\python.exe' scripts\generate_sensor_data.py --scenario unbalance_fj01 --start $a ^
    --minutes 4320 --interval 60 --seed 42 --out "data\raw_docs\设备传感器仿真数据_72h_unbalance_fj01.csv"
```

场景可选：`normal` / `unbalance_fj01` / `rub_fj01` / `watemp_fj03`（见 `docs/传感器数据资产说明.md` §3）。

## 4. Windows：配置 `.env`

除 DeepSeek 与数据库配置外，新增 Embedding 服务配置（有默认值，不填也能跑）：

```
EMBEDDING_BASE_URL = http://localhost:30000/v1
EMBEDDING_MODEL =            # 留空则自动向服务查询模型 id
EMBEDDING_DIM = 1024
EMBEDDING_API_KEY = not-needed
```

## 4.5 Windows：初始化数据库表（首次执行一次）

```powershell
$env:PYTHONPATH='.'
& 'D:\Anaconda\python.exe' scripts\init_db.py
```

在 `industrial_intelligent_diagnosis_platform` 库中创建 4 张诊断表：
`diagnosis_record`（诊断记录）、`diagnosis_evidence`（证据链）、`diagnosis_report`（报告正文）、
`hitl_review`（人工审核）。脚本最后会做一次连通性自检。

**诊断会话的 checkpoint** 存在 `data/checkpoints/langgraph.sqlite`，**服务重启后仍可恢复**中断中的
澄清/审核会话；如需退回进程内模式，设 `CHECKPOINT_BACKEND=memory`。

## 5. Windows：启动服务（第 3 步）

```powershell
$env:PYTHONPATH='.'
& 'D:\Anaconda\python.exe' -m uvicorn apps.api.main:app --host 0.0.0.0 --port 8000 --reload
```

## 6. 启动自检（建议每次演示前跑）

```powershell
$env:PYTHONPATH='.'
& 'D:\Anaconda\python.exe' scripts\check_env.py
```

自检内容：Python 版本、关键依赖、Embedding 服务连通性与维度、A3 数据可用性、LLM 通道。

## 7. 常见问题

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| `EmbeddingUnavailable: 无法连接 http://localhost:30000/v1` | WSL2 模型服务未启动 / 端口未转发 | 回到第 1 步启动服务，用 `/v1/models` 验证 |
| 维度不匹配（返回 768 或 512） | 服务加载的不是 bge-large-zh-v1.5 | 检查 WSL2 启动参数里的 `--model-path` |
| `ModuleNotFoundError: openai / langgraph` | 依赖装到了别的解释器 | 确认用 `& 'D:\Anaconda\python.exe' -m pip install` 安装 |
| `pip` 报 Access denied | 文件沙箱阻止写 `D:\Anaconda` | 手动在终端执行第 2 节命令，或申请提权 |
| 检索结果为空 | 知识库索引未建立 | 先跑索引构建脚本（见 RAG 模块说明） |
| 诊断结论"未发现异常" | 激活的是 normal 数据集 | 切换数据集后重启服务（见数据资产说明 §1） |
| 诊断能跑通但数据库没记录 | 未建表 / MySQL 未启动 | 执行 `scripts/init_db.py`；**诊断链路不会因 DB 故障中断**，会退回文件存储，错误见 `persistence.last_error()` |
| 服务重启后审核会话失效 | 设了 `CHECKPOINT_BACKEND=memory` | 去掉该变量，即用 `data/checkpoints/langgraph.sqlite` 持久化 checkpoint |
