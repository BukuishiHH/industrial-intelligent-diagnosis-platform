## 3. 测试方案

### 3.1 测试分层（去掉混沌/大规模安全测试）

| 层级 | 范围 | 工具 | 关键覆盖点 |
| --- | --- | --- | --- |
| 单元测试 | 各模块纯函数/工具 | pytest | 切块逻辑、特征计算、异常判定、State 序列化、工具 Schema 校验 |
| 集成测试 | 模块间真实协作 | pytest + testcontainers | RAG 检索→工具调用→State 流转；DB 读写；API 路由 |
| 简单 E2E | 用户主路径 | pytest + httpx（或 Playwright） | 完整问诊闭环、人工复核闭环、文档上传 |
| AI 评测 | RAG 与推理质量 | 评测脚本（ml/eval_metrics.py） | 见 3.2 |

### 3.2 AI 评测指标

| 指标 | 定义 | MVP 目标值 |
| --- | --- | --- |
| 检索命中率@5 | top5 中是否包含标注的正确答案（RAG 评测集） | ≥ 0.8 |
| 证据相关性 | 证据片段与问题的相关性人工评分均值 | ≥ 4.0/5 |
| 诊断准确率 | 端到端诊断结论与标注故障一致的比例（评测集） | ≥ 0.7（仿真数据） |
| 幻觉率 | 报告中无证据支撑的断言占比 | ≤ 10% |
| 置信度校准 | 高置信度结论的正确率与置信度接近 | 高置信(>0.8)结论正确率 ≥ 0.7 |
| 知识缺口识别 | 无证据时正确触发降级提示的比例 | ≥ 0.8 |

> 评测集：从 27 份文档与仿真故障中构建 20-30 条带标准答案的评测样本（B 负责标注，A 负责脚本）。

### 3.3 测试准入准出

| 阶段 | 准入条件 | 准出条件 |
| --- | --- | --- |
| 单元测试 | 代码提交通过静态检查（ruff/black） | 单元测试通过率 100%，覆盖率 ≥ 60%（核心模块） |
| 集成测试 | 单元测试通过 | 集成测试全绿；无未修复的高严重度缺陷 |
| E2E 测试 | 集成测试通过 | 3 条主路径用例全绿（问诊/复核/上传） |
| AI 评测 | E2E 通过 | 3.2 指标达到 MVP 目标值 |
| 发布验收 | 全部测试通过 | MVP 验收指标（第 4 章）全部满足 |

## 6. Git 分支策略、Commit 规范与 CI 门禁

### 6.1 分支策略（Gitee Flow 简化版，2 人够用）

- `main`：稳定分支，随时可演示/发布；合并需通过 CI 门禁。
- `dev`：开发集成分支，日常合并点。
- `feature/<模块>`：功能分支（如 `feature/rag`、`feature/langgraph`、`feature/frontend`），完成后 PR 合并到 `dev`。
- `hotfix/*`：紧急修复分支，直接合 `main` 并回合 `dev`。
- 禁止直接向 `main` 推送（PR 方式合入）。

### 6.2 Commit 规范（Conventional Commits）

```
<type>(<scope>): <subject>

feat(rag): 增加混合检索与 Rerank
fix(workflow): 修复 HITL 断点恢复失败
docs(docs): 更新 02 模块设计错误码表
test(sensor): 补充特征计算单元测试
```

- type：`feat` / `fix` / `docs` / `test` / `refactor` / `chore` / `perf`；
- scope：`rag` / `workflow` / `sensor` / `api` / `frontend` / `tools` / `docs` 等；
- 中文描述，动词开头，一句话说清变更。

### 6.3 CI 门禁（GitHub Actions / Gitee Go 示意）

```yaml
name: ci
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }
      - run: pip install -r requirements.txt
      - run: ruff check .          # 静态检查
      - run: pytest tests/unit tests/integration -q   # 测试
      - run: python -m build       # 构建校验
```

- 门禁规则：静态检查零错误；单元+集成测试全绿；`main` 分支 PR 必须通过 CI 才能合入。
