## 二、如何使用

### 2.1 启动（三步，顺序不能颠倒）

```powershell
# ① WSL2 Ubuntu：先启动 bge 向量模型服务（端口 30000）
#    验证（Windows 侧）：Invoke-WebRequest http://localhost:30000/v1/models -UseBasicParsing

# ② Windows：准备数据（每次演示前重跑，让末端跟到当前时刻）
$a = (Get-Date).AddHours(-72).ToString('yyyy-MM-ddTHH:mm:ss')
& 'D:\Anaconda\python.exe' scripts\generate_sensor_data.py --scenario unbalance_fj01 `
    --start $a --minutes 4320 --interval 60 --seed 42 `
    --out "data\raw_docs\设备传感器仿真数据_72h_unbalance_fj01.csv"

# ③ 构建索引（首次或文档变更后；约 6s）＋ 启动服务
$env:PYTHONPATH='.'
& 'D:\Anaconda\python.exe' scripts\build_index.py
& 'D:\Anaconda\python.exe' -m uvicorn apps.api.main:app --host 0.0.0.0 --port 8000 --reload
```

> 切换演示场景：把 `SENSOR_DATA_PATH` 指向对应 CSV，或替换默认数据集文件名。
> 可用场景：`normal` / `unbalance_fj01` / `rub_fj01` / `watemp_fj03`。

### 2.2 调用接口

所有接口需 `Authorization: Bearer <token>`（用 `POST /user/login` 获取）。

**① 发起诊断**

```bash
curl -X POST http://localhost:8000/diagnosis/query \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"query":"FJ-01 最近振动一直往上涨，是什么原因？"}'
```

返回三种状态之一：

| status | 含义 | 下一步 |
| --- | --- | --- |
| `awaiting_clarification` | 未指定设备 | 调 `/diagnosis/review` 带 `device_id` |
| `awaiting_review` | 已出结论，等人工确认 | 展示 `payload.card`，调 `/diagnosis/review` 带 `decision` |
| `completed` | 流程结束（非检修意图，或已完成报告） | — |

**② 澄清 / 审核**

```bash
# 澄清：补设备位号
curl -X POST http://localhost:8000/diagnosis/review -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"thread_id":"th_xxx","device_id":"FJ-01"}'

# 确认：生成并持久化报告
curl -X POST http://localhost:8000/diagnosis/review -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"thread_id":"th_xxx","decision":"confirm"}'
```

**③ 取报告 / 历史**

```bash
curl http://localhost:8000/diagnosis/report/<report_id> -H "Authorization: Bearer <token>"
curl http://localhost:8000/diagnosis/history    -H "Authorization: Bearer <token>"
```

### 2.3 直接用 Python 调（不经过 HTTP）

```python
from packages.service.diagnosis_service import DiagnosisService

svc = DiagnosisService(data_path="data/raw_docs/设备传感器仿真数据_72h_unbalance_fj01.csv")
out = svc.start("FJ-01 最近振动一直往上涨，是什么原因？", user_id=7)
print(out["status"])                       # awaiting_review
print(out["payload"]["card"]["summary"])   # 一句话结论
out = svc.resume(out["thread_id"], {"decision": "confirm", "user_id": 7})
print(out["report_id"], len(out["report_markdown"]))
```

### 3.3 数据隔离（重要）

诊断记录与报告**按用户隔离**，四个面都有校验：

| 面 | 规则 | 越权返回 |
| --- | --- | --- |
| 历史列表 GET /diagnosis/history | 只返回当前登录用户发起的诊断 | 空列表 |
| 报告详情 GET /diagnosis/report/{id} | 校验诊断记录的 user_id | 404（与"不存在"同样返回，不暴露存在性） |
| 会话状态 GET /diagnosis/state/{thread} | 校验 checkpoint 中记录的发起人 | 403 |
| 澄清/审核 POST /diagnosis/review | 只有发起人本人能继续该会话 | 403 |

- 归属写入点在 A4（save_diagnosis 记录 user_id）与 A5（报告文件副本元数据也带 user_id，供数据库不可用时的文件兜底同样校验）。
- **安全默认**：user_id 缺失时一律拒绝（宁可查不到，也不越权可见）。
- 回归用例见 `scripts/check_user_isolation.py`（离线可跑，不依赖大模型）。

### 3.4 测试要点（怎么判断"对"）

- **A3**：`normal` 数据集应**零阈值/趋势命中**（防误报）；`unbalance` 应命中 v1 报警 + 24h 渐变上升；`rub` 应命中停机值 + 10min 突变 + 瓦温速率；`watemp` 应命中瓦温二级报警。
- **A4**：根因应为"叶轮积灰结垢致转子不平衡"（unbalance 场景）；`validation_problems` 必须为空（说明所有证据都溯源成功）。
- **耗时**：全链路 ≤60s；若 A2 明显超过 15s，检查重排是否触发超时降级（`search_trace.a2_degraded`）。
- **报告**：`data/reports/{report_id}.md` 与 `.json` 应同时生成，`index.jsonl` 追加一行。

按 `演示SOP_设备检修诊断.md` §3 的 4 个用例走一遍：unbalance / rub / watemp 三个故障场景 + normal 反向用例（应输出"未发现明确故障"）。

## 四、前端控制台

技术栈：React 18 + TypeScript + Vite 5 + React Router 6（零 UI 组件库依赖）。详见 frontend/README.md。

### 4.1 启动

    cd frontend
    $env:npm_config_cache = (Join-Path $PWD '.npm-cache')
    npm install
    npm run dev            # http://127.0.0.1:5173

开发期由 Vite 代理 /api → http://127.0.0.1:8000，因此**后端必须先启动**。

### 4.2 页面

## 五、常见问题

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| `EmbeddingUnavailable` | WSL2 模型服务未启动 | 回§2.1 第①步 |
| "该时段无数据" / 覆盖率很低 | 数据过期（末端未跟到当前时刻） | 重跑数据生成脚本 |
| 诊断结论"未发现异常" | 激活的是 normal 数据集 | 切换到故障场景数据集 |
| 检索结果为空 | 索引未构建 | `python scripts/build_index.py` |
| `ModuleNotFoundError` | 用错解释器 | 统一用 `D:\Anaconda\python.exe`（3.12.4） |
| 全链路超过 60s | LLM 服务端波动 / 重排未降级 | 检查 `search_trace`；可调 `RERANK_TIMEOUT` |
| 服务重启后审核会话失效 | `MemorySaver` 未持久化 | 重新发起诊断（后续换 SqliteSaver） |
