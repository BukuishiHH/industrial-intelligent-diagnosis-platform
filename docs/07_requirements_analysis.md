## 1. 需求概述

### 1.1 项目目标

建设面向工业场景的 AI 设备故障诊断平台，覆盖 **27 份工业文档（约 1109 页、约 5091 个向量块）** 与 **4 台设备 24 个传感器**，采用 **LangGraph 单图统一编排** 和 **A2A + MCP 双协议分层架构**，将 AI 诊断推进到生产可用级别。

### 1.2 需求范围

本期范围包括：

- 工业文档知识库全链路：接入、解析、OCR、切块、向量化、混合检索、溯源、版本管理。
- 传感器数据处理全链路：接入、清洗、对齐、特征提取、异常检测、统一数据服务。
- AI 诊断能力：任务理解、信息澄清、假设生成、证据验证、置信度评估、维护建议、报告生成、人工复核、案例回流。
- 编排与协议：LangGraph 单图、A2A 协作、MCP 工具标准化、可靠性策略。
- 平台支撑：认证授权、审计、配置、可观测、成本控制、备份恢复。
- 典型场景：实时异常诊断、人工问诊、知识问答、复核回流。

本期不包括：设备自动控制、传感器施工、公众移动 App、深度备件采购联动、预测性维护高级能力。

### 1.3 需求编号规则

- 功能性需求：`FR-<模块>-<序号>`，如 `FR-01-03`
- 非功能性需求：`NFR-<类别>-<序号>`，如 `NFR-PERF-02`
- 架构需求：`AR-<序号>`
- 验收标准：`AC-<类别>-<序号>`
- 优先级：MoSCoW（M 必须、S 应该、C 可以、W 本期不做）

## 2. 业务需求

### 2.1 业务痛点

| 编号 | 痛点 | 现状 | 平台应对 |
| --- | --- | --- | --- |
| BR-01 | 人工排查耗时长 | 跨文档、跨系统人工比对，小时/天级 | 检索 + 数据服务 + 多步诊断，分钟级辅助定位 |
| BR-02 | 经验依赖度高 | 依赖少数资深工程师，夜班/异地能力弱 | SOP 化、案例化、Agent 推理链沉淀 |
| BR-03 | 知识传承困难 | 经验留在个人，新人成长慢 | 诊断留痕、案例回流、知识库持续更新 |
| BR-04 | 知识与数据割裂 | 文档、时序、工单分散 | 统一任务上下文，知识与数据双证据融合 |
| BR-05 | 结论不可解释 | 人工难复现，AI 有幻觉风险 | 证据链、引用溯源、置信度、人工复核 |
| BR-06 | 工具扩展成本高 | 接口异构，改一处牵全身 | MCP 工具化 + A2A 解耦 + 插件机制 |

### 2.2 业务场景

| 编号 | 场景 | 触发 | 关键参与者 | 成功标准 |
| --- | --- | --- | --- | --- |
| BS-01 | 实时异常诊断 | 传感器告警 | 值班工程师、A03/A04/A05/A06/A07/A09 | 报告 P95 ≤ 60s，证据可溯 |
| BS-02 | 人工问诊诊断 | 用户自然语言 | 设备工程师、A02/A03/A04/A06 | 输出候选故障排序与建议 |
| BS-03 | 知识规程问答 | 用户提问 | 工程师、A03 | 答案带原文页码引用 |
| BS-04 | 复核回流 | 工程师复核 | 专家、A09/A10 | 结论沉淀案例，错误进入错题集 |
| BS-05 | 趋势预警（试点） | 趋势异常 | 主管、A04/A05/A06 | 提前预警并给维护窗口 |

## 8. 约束与假设

### 8.1 约束

| 编号 | 约束 |
| --- | --- |
| CON-01 | 首批知识库规模为 27 份文档、约 1109 页、约 5091 向量块 |
| CON-02 | 设备侧固定为 4 台设备、24 个传感器（本期） |
| CON-03 | 必须使用 LangGraph 单图统一编排 |
| CON-04 | 必须引入 A2A + MCP 双协议分层架构 |
| CON-05 | AI 只提供辅助建议，不执行设备控制 |
| CON-06 | 支持私有化部署和工业网络隔离 |
| CON-07 | 量化指标需在需求评审阶段确认并冻结 |

### 8.2 假设

1. 文档可提供电子版或清晰扫描件。
2. 传感器数据可通过现场协议稳定获取。
3. 业务方提供典型故障场景和专家复核资源。
4. 模型和算力资源可按计划到位。
5. 现场网络允许平台与采集/业务系统最小必要通信。
6. 用户接受“AI 辅助 + 人工确认”的定位。
